# Telegram-бот знакомств 18+

Локальный MVP на Python 3.12, aiogram 3 и SQLAlchemy 2. Интерфейс на русском. Для запуска нужны ваш токен BotFather и доступ к Telegram API (возможно, ваш собственный прокси). Без внешнего AI работают все основные функции.

## Быстрый запуск в Windows PowerShell

1. Установите Python 3.12 с https://www.python.org/downloads/windows/ (в установщике отметьте Add Python to PATH). Откройте новый PowerShell и проверьте `py -3.12 --version`.
2. Скачайте репозиторий через GitHub → Code → Download ZIP, распакуйте. Откройте PowerShell в папке `telegram_dating_bot_v2` (в проводнике в адресной строке введите `powershell`). Все команды ниже выполняются в этой папке.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
notepad .env
```

Если PowerShell запрещает активацию, можно разрешить её только для текущего окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Альтернатива без активации: в командах вместо `python` используйте `.\.venv\Scripts\python.exe`.

3. В Telegram откройте проверенного @BotFather, отправьте `/newbot`, задайте название и уникальный username с окончанием `bot`. Скопируйте полученный токен в `BOT_TOKEN` файла `.env`. Не отправляйте токен в чат, GitHub и скриншоты. Если токен раскрыт, перевыпустите его через BotFather.
4. Заполните настройки:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН
DATABASE_URL=sqlite+aiosqlite:///./dating.db
ADMIN_IDS=
PROXY_URL=
AI_ENABLED=false
AI_API_KEY=
LOG_LEVEL=INFO
```

В `ADMIN_IDS` укажите Telegram ID администраторов через запятую. Если не знаете свой ID, его можно получить из экспорта данных своего аккаунта Telegram или доверенного средства определения ID. Не используйте username вместо числа.

5. Если прямой доступ к api.telegram.org:443 блокируется, настройте собственный или доверенный платный прокси отдельно и заполните `PROXY_URL`: `http://USER:PASSWORD@HOST:PORT` либо `socks5://USER:PASSWORD@HOST:PORT`. Это форматы, а не рабочие адреса. Спецсимволы учётных данных URL-кодируются. Без прокси используется прямое соединение. Не заменяйте домен Telegram случайным IP. SSL-проверка остаётся включённой. SOCKS-зависимости включены в установку. Для SOCKS5 разрешение домена выполняет прокси.
6. Примените миграции и проверьте связь:

```powershell
python -m alembic upgrade head
python scripts/check_connection.py
python -m app.main
```

Проверка связи отдельно показывает DNS, прямой TCP, HTTPS через настроенный прокси и безопасный getMe. Без BOT_TOKEN getMe пропускается. Скрипт не выводит токен и пароль прокси. Успешный DNS не означает доступность Telegram по TCP. Если getMe не прошёл, исправьте токен/сеть/прокси перед запуском.

7. Откройте своего бота в Telegram и отправьте `/start`. Для проверки лайков нужны два реальных аккаунта 18+ с опубликованными взаимно подходящими анкетами.
8. Остановка: `Ctrl+C`. После выключения компьютера откройте PowerShell в той же папке:

```powershell
.\.venv\Scripts\Activate.ps1
python -m alembic upgrade head
python -m app.main
```

Анкеты и черновики хранятся в `dating.db`. Для продолжения черновика после перезапуска отправьте `/start` и нажмите «Продолжить». Бот работает только пока компьютер включён и процесс запущен. Не запускайте одновременно несколько polling-процессов для одного токена.

## Функции

- Подтверждение 18+ и принятие правил, пошаговая FSM-регистрация, валидация возраста 18–100, назад/пропустить/отмена, черновик в БД, предпросмотр и публикация.
- Имя, возраст, пол (можно не указывать), город, цель, интересы и описание, взаимные возрастные/городские/гендерные предпочтения.
- 1–5 Telegram-фотографий до 10 МБ, главная фотография, просмотр, удаление и добавление через редактирование. Принимается тип Telegram Photo, документы и видео не принимаются. Telegram преобразует Photo в JPEG; оригинальные байты не скачиваются и не проверяются антивирусом.
- Редактирование проходит те же шаги с предварительно заполненным черновиком. Поля поиска тоже редактируются; публикация применяет изменения атомарно. Для добавления фото при предпросмотре есть отдельная кнопка.
- Поиск исключает себя, скрытых, заблокированных, забаненных, уже оценённых и не подходящих по взаимным фильтрам. Город сопоставляется без учёта регистра; расстояние и геокодирование не реализованы.
- Лайки/пропуски, атомарное создание единственного взаимного совпадения, список исходящих симпатий и количество входящих; личности входящих лайков отдельно не раскрываются.
- Уведомления о совпадениях сохраняют статус доставки в БД и повторяются после сетевого сбоя/перезапуска. При падении между отправкой и фиксацией возможен повтор уведомления (доставка минимум один раз).
- Контакты — только публичный @username после отдельного согласия обоих; телефон и Telegram ID не раскрываются. Отзыв согласия, удаление совпадения и блокировка прекращают последующий доступ. Ранее отправленные сообщения отозвать нельзя.
- Жалобы по шести категориям, очередь администратора, просмотр всех фото по жалобе, бан/разбан/скрытие, закрытие жалобы, журнал действий. Автоматической модерации фото нет.
- Удаление пользователя каскадно удаляет анкету, фото, предпочтения, лайки, совпадения, согласия, блокировки, жалобы и черновик. Неиспользуемые пользовательские интересы очищаются. Telegram-сообщения и внешние резервные копии не удаляются автоматически.

## Совместимость и AI

Локальная детерминированная формула: цель 30%, интересы 25% (Jaccard), взаимный возраст 20%, город 15%, взаимные предпочтения по полу 10%. Веса находятся в `Settings.compatibility_weights` и могут переопределяться JSON-переменной `COMPATIBILITY_WEIGHTS`. Пропущенные интересы и неопределённые цели исключаются с перенормировкой весов и явным указанием недостатка данных. Оценка симметрична; это условный показатель, не научная вероятность отношений, сексуального интереса или согласия.

AI по умолчанию выключен. Абстракция `AIProvider` допускает другого провайдера. HTTP-реализация поддерживает явно настроенный HTTPS endpoint с форматом chat completions. Для включения оператор сначала заполняет данные провайдера в политике, затем задаёт `AI_ENABLED=true`, `AI_API_KEY`, `AI_API_URL` (полный URL endpoint), `AI_MODEL`. Оба участника отдельно разрешают передачу текста в настройках. Передаются только описания, интересы, цели, оценка и факторы. Тексты могут сами содержать личные сведения; это объясняется до согласия. Фото не анализируются.

`AI_DAILY_LIMIT=20` ограничивает суммарное число попыток в сутки UTC для всего бота (включая неудачные), `max_tokens=220`, таймаут 10 секунд. Это лимит запросов и выхода, не денежный бюджет; задайте денежный лимит также у провайдера. AI не меняет процент. При отсутствии настроек, согласий, исчерпании лимита или сетевой ошибке используется локальное объяснение. AI-запросы используют отдельное HTTPS-соединение напрямую; Telegram-прокси применяется только к Telegram.

## Администрирование

Только ID из `ADMIN_IDS` имеют доступ. Команды выполняются в личном чате:

```text
/admin
/admin stats
/admin reports
/admin view TELEGRAM_ID
/admin ban TELEGRAM_ID
/admin unban TELEGRAM_ID
/admin hide TELEGRAM_ID
/admin resolve НОМЕР_ЖАЛОБЫ
```

Модератор получает ID из очереди жалоб, просматривает анкету/фото, применяет действие и закрывает жалобу. В статистике доступны общее число пользователей, анкет, оценок (включая пропуски), совпадений и опубликованных анкет. Публичный запуск требует назначенного модератора и заполненных правил.

## Проверки и устройство

```powershell
python -m pytest -q
python -m ruff check .
python -m alembic check
```

Тесты используют временную SQLite и Telegram-моки; платные API и токен не нужны. Есть тест реального Dispatcher/FSM через синтетические Telegram Update, проверки регистрации, возраста, сохранения после открытия БД заново, фильтров, конкурентных лайков, контактов, блокировок, каскадного удаления, прав администратора, фото, повторной доставки и AI-согласий/лимита. Живой Telegram и внешний AI автоматически не проверены.

`app/handlers` отвечает за Telegram, `app/services` — бизнес-логику и AI, `app/models.py` — схему, `app/database.py` — транзакции. SQLAlchemy ORM параметризует запросы, внешние ключи SQLite включены. Мутации используют `BEGIN IMMEDIATE` в SQLite, уникальные/составные ключи защищают от повторов. Для PostgreSQL используется транзакционный advisory lock, нужно установить `asyncpg`, сменить DATABASE_URL на `postgresql+asyncpg://...` и прогнать миграции/тесты. PostgreSQL в этой среде не проверен; при росте нагрузки глобальную блокировку стоит заменить упорядоченными блокировками строк без изменения интерфейса сервиса.

Приложение принимает сообщения только в личных чатах, не использует HTML parse_mode для пользовательского текста, ограничивает частоту действий до 2 в секунду на пользователя и оценок до 60 в час в базе. Дубликаты callback ID фильтруются в памяти, оценки и совпадения дополнительно идемпотентны в БД; шаги регистрации и фото защищены от устаревших кнопок. Бизнес-транзакции повторно проверяют права. Логи содержат фиксированные диагностические сообщения, без пользовательского ввода и текста исключений с секретами.

`.env`, БД и виртуальное окружение исключены из Git. `requirements.lock.txt` фиксирует проверенные версии; `requirements.txt` задаёт допустимые диапазоны. CI запускает Ruff, тесты и миграции на Windows/Python 3.12.

## Ограничения перед публичным запуском

Это MVP, не аудированный коммерческий сервис. Возраст подтверждается пользователем; верификация документов не предусмотрена. Вручную заполните `docs/RULES.md`: оператор, контакт, сроки хранения/резервирования, провайдер и условия AI; нужна юридическая проверка. Настройте модерацию и резервное копирование. SQLite-файл содержит персональные данные без шифрования на уровне приложения — ограничьте права ОС, используйте шифрование диска и защищайте копии. Публичные списки ограничены первыми 30 совпадениями/жалобами и 50 именами симпатий; пагинация, геопоиск, мультимодальность, автоматическая модерация и система апелляций не реализованы. Фотоподписи ограничены 900 символами; полные данные хранятся в базе. Прокси и токен пользователь настраивает самостоятельно.
